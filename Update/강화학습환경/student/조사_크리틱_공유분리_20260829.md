# 조사: PPO(+LSTM) 에서 actor/critic 분리 vs 공유 (2026-08-29, 에이전트 웹 조사)

질문(사용자): "크리틱을 우리처럼(분리, `--model-vf-share-layers false`) 하는 사람이 있는지".

## 결론
저차원 연속제어·self-play 계열에서는 **분리가 표준**. 공유는 이미지 입력(Atari/Procgen)과 OpenAI Five(거대 LSTM 하나)에 남아 있음. RLlib 2.54 new stack 에서 `vf_share_layers=False` 면 `actor_encoder`/`critic_encoder` 가 **각각 build** 되고 LSTM 상태도 분리 보관(`ray/rllib/core/models/base.py:362-388`, `ppo_catalog.py:82` 로컬 확인). 현재 실행 = MLP256-256→LSTM128 두 벌.

## 발견
- 저차원 연속제어의 대규모 ablation 은 Andrychowicz 하나이고, CleanRL/SB3/37-details 의 "연속제어=분리" 관행의 근거. 반대 증거는 이미지 입력(PPG)과 rl_games(value 정규화 조건부)뿐.
- 간섭 메커니즘은 문헌에 이름이 있음: PPG "한 목적의 최적화가 다른 목적을 방해", IDAAC "가치가 더 많은 정보 필요 → 공유 시 과적합", Garcin 2025 "분리하면 actor 표현은 행동, critic 표현은 value·dynamics 로 특화". 이 프로젝트의 8월 초 "vf 기울기가 정책 피처를 부숨"과 같은 현상.
- 재귀(LSTM) 정책도 분리가 기본(sb3-contrib, rsl_rl, LAG). 공유 LSTM 은 CleanRL Atari 와 OpenAI Five(LSTM 이 파라미터의 84%라 두 벌이 비현실적).
- 분리의 단점 둘: 파라미터 2배(여기선 타워당 ~27만, 무시 가능), critic 이 정책 피처를 못 씀(16-D 관측에선 공유할 피처가 거의 없음).
- RLlib 구 API stack 에선 `use_lstm=True` 면 `vf_share_layers=False` 가 무시되어 공유됐음(issue #15166). new stack 은 분리됨(로컬 소스 확인).
- vf_loss_coeff 관행: 분리 0.5(CleanRL/SB3/sb3-contrib)~1.0(RLlib/rsl_rl/LAG). 어느 문헌도 0.01 을 쓰지 않음 — 그 값은 공유 인코더에서 가치 기울기를 죽이는 임시방편.
- (에이전트 추론, 출처 없음) 분리+Adam 이면 vf_loss_coeff 는 critic 실효 lr 을 거의 안 바꿈. 남는 효과는 global grad-clip 1.0 에서 value 기울기 몫뿐.
- 로컬 문구 stale: `train_curriculum.py:303` 도움말 "vf_share_layers is True, so this gradient also flows through the policy encoder" — 배트는 false. 동작 무관.

## 권고 (이 규모: MLP 256-256 → LSTM 128, batch 16k, 10 Hz, 200 s)
분리 유지. 조건이 Andrychowicz 실험과 가장 가깝고 도그파이트 참조 구현(LAG)·재귀 PPO 표준(sb3-contrib, rsl_rl)이 전부 actor/critic RNN 을 따로 둠. 분리 상태에서 vf_loss_coeff 는 관행 범위 0.5~1.0(현재 0.5 적절). 분리의 추가 이점: critic 은 제출되지 않으므로 critic 을 더 넓게(512-512) 두거나 critic 입력에만 특권 정보(상대 HP 등 9-패킷 밖 값)를 넣는 비대칭 critic 이 규칙 위반 없이 가능 — RLlib new stack 에선 커스텀 RLModule 필요, 별도 실험 항목. 미확인: AlphaStar 코어 공유 여부, AOS 논문 전문.
